# Sky Time Machine (25년 하늘 비교기)

| 항목 | 내용 |
| --- | --- |
| ID | `sky-time-machine` |
| 상태 | **1차 구현됨** (분석 패널 "Additional analyses"에서 열림) |
| 담당 | 김재현 (`rreenactt`) |
| 출력 종류 | view, overlay |
| 최소 SPHEREx 방문 횟수 | 1 (과거 탐사와 비교하므로 SPHEREx 방문이 1회여도 동작) |
| 적용 대상 | 모든 좌표 |
| 화면 배치 | 추가 분석 목록 → "Run" → 다 받으면 패널 왼쪽 탭으로 열림 (결정 #42) (기본 시야 8′) |
| 데이터 | 2MASS, WISE(AllWISE·cryo), NEOWISE, SPHEREx DR1 (모두 IRSA), Gaia DR3 |

## 1. 무엇을 알려주나

같은 하늘 조각을 2MASS(약 2000년) → WISE(2010) → NEOWISE(2014–2024) → SPHEREx(2025–)의 실제 관측 순서로 넘겨 본다. 25년 동안 쌓인 이동을 Gaia 예측 경로와 함께 보여주고, 사용자가 시점마다 별 위치를 찍어 이동량(″/년)을 직접 잴 수 있다.

## 2. 왜 필요한가

- SPHEREx는 한 지점을 6개월 간격으로 몇 번만 찍었고 픽셀이 6.15″로 크다. 느린 천체는 SPHEREx만으로는 거의 안 움직인다. 25년 기준선이면 같은 천체가 수십–수백 ″ 움직여 눈에 보인다(Barnard's Star 약 250″).
- SPHEREx 방문이 1회뿐인 지점("추가 분석 필요" 상태)에서도 과거 탐사와 비교해 판단할 수 있게 한다.

## 3. 입력 데이터

| 미션 | 컬렉션 (IRSA SIA2) | 영상 | 받는 곳 |
| --- | --- | --- | --- |
| 2MASS | `twomass_allsky` | Atlas 타일 J·H·Ks (약 2″/픽셀) | IRSA IBE 잘라내기 |
| WISE | `wise_allsky`, `wise_3bandcryo`, `wise_2bandcryo` | L1b 단일 노출 W1·W2 (2.75″) | AWS `nasa-irsa-wise` 바이트 범위, 실패 시 IBE |
| NEOWISE | `neowiser` | L1b 단일 노출 W1·W2 | AWS `nasa-irsa-wise` 바이트 범위, 실패 시 IBE |
| SPHEREx | `spherex_dr1` | L2b D1–D6 (6.15″) | AWS `nasa-irsa-spherex` 바이트 범위 |
| Gaia DR3 | ESA Gaia Archive 우선 ([결정 #27](../decisions.md)) | 고유운동 큰 별 | TAP |

시각은 공개일이 아니라 SIA2의 `t_min`·`t_max`(실제 관측 시각)를 쓴다.

## 4. 방법

1. **검색:** 미션마다 SIA2를 동시에 묻는다. `neowiser`는 한 지점에 노출이 수천 장이라 한 번에 약 25초가 걸려, `TIME`을 8구간으로 나눠 동시에 묻는다(약 5초, 같은 행 수 확인, 경계 중복은 노출 id로 제거).
2. **시점 묶기:** 밴드별로 노출을 20일 간격 기준으로 관측 통과(방문)로 묶는다.
3. **WISE·NEOWISE 합성 ([결정 #26](../decisions.md)):** 공식 unWISE 시간분해 영상은 이미지로 공개되어 있지 않다(카탈로그만 있음). 그래서 통과마다 L1b 노출을 최대 5장(통과 전체에 고르게) 받아 MAGZP 22.5로 맞추고 배경 중앙값을 뺀 뒤 픽셀별 중앙값으로 합친다. 화면·근거에 "이 도구에서 계산한 합성"으로 표시한다.
4. **2MASS:** 같은 밤의 Atlas 타일 중 시야 중심에 가까운 것 최대 4장. **SPHEREx:** 통과마다 노출 1장(가운데), 시야 중심 파장을 `WCS-WAVE`로 계산해 표시한다.
5. **정렬:** 각 영상의 TAN·SIN(SIP 포함) WCS를 직접 읽어 공통 격자(256×256, 북쪽 위·동쪽 왼쪽)에 쌍선형 재투영한다. 자료 없는 픽셀은 빗금으로 보인다(검은 하늘로 칠하지 않음).
6. **이동 표시:** 사용자 표시 위치, 측정 위치(밝기 중심), Gaia 예상 위치·경로(2016.0 + 선형 고유운동, 시차 무시)를 구분해 그린다. 표시 위치끼리 이은 점선은 실제 경로가 아니라고 적는다.

### 영상 받기 속도 (2026-11-14 측정)

- IRSA IBE 잘라내기는 한 클라이언트에 동시 2개까지만 받고 3번째부터 바로 503을 준다. SIA2는 8개, DataLink는 16개, S3는 80개 동시도 문제없었다.
- 그래서 WISE·NEOWISE는 같은 원본 파일이 있는 IRSA의 AWS 공개 버킷(SIA2 `cloud_access`의 키)에서 헤더와 시야 주변 행만 읽는다. IBE 잘라내기와 같은 방식(WCS는 그대로, 기준 픽셀만 이동)이라 결과 위치가 같다.
- IBE 요청(2MASS와 S3 실패 시 대체 경로)은 서버 프로세스 안에서 동시 2개로 묶고, 503이면 0.4–1초 뒤 시간 예산 안에서 다시 시도한다.
- 한 시점의 노출은 모두 동시에 읽고, 브라우저는 시점을 8개씩 요청한다.
- Barnard's Star 8′ 시야 27시점: 약 90초 → 48초(한국 PC, 미국 S3에서 직접 받아 회선 대역폭이 병목).

## 5. 출력

- **탭:** Timeline / Compare two dates / Motion / Evidence (화면 문구는 영어)
- **타임라인:** 실제 관측 기간 막대(관측 없는 해는 비어 있음), 받은 시점은 진하게
- **근거:** 시점마다 쓴 노출 id·원본 URL·관측 시각, 합성 방식, 빠진 노출과 이유

## 6. 한계와 주의

- 미션마다 파장이 달라 **밝기 비교와 차분은 하지 않고 위치만 비교한다** ([`PLAN.md` 4장](../PLAN.md#다른-탐사와-비교할-때)).
- 미션마다 픽셀 크기·퍼짐이 달라 별 모양이 다르다. 이를 움직임으로 보지 않도록 안내한다. 이동량은 가장 거친 쪽 정밀도로 판단한다.
- 밝은 별은 2MASS·WISE에서 포화되어 밝기 중심이 몇 ″ 어긋날 수 있다(Barnard's Star W1에서 약 9″).
- 목표가 프레임 가장자리 밖인 노출은 "격자와 겹치는 영역 없음"으로 빠진다(검색 반경이 시야보다 넓기 때문).
- S3 행 읽기는 프레임 전체 폭(1016픽셀)을 받아 IBE 잘라내기보다 바이트가 약 4배 많다.

## 7. 검증

- Barnard's Star 시야에서 Gaia DR3 기준 별을 각 시점으로 옮겨 비교: 2MASS(2000.41) 0.06″/0.02″, WISE(2010.21) 0.11″/−0.20″, NEOWISE(2014.22·2024.21) 0.48″, SPHEREx(2025.64) 0.08″/−0.35″ 오프셋 (흩어짐 0.3–1.0″, 격자 1.88″).
- 사용자 표시로 잰 Barnard's Star 이동 247.4″ / 23.81년 = 10.39″/년, Gaia DR3와 일치.
- S3 경로 도입 후: NEOWISE 2014.22→2024.21 사이 밝기 중심 이동 105″ / 10년 = 10.5″/년 (Gaia 10.36″/년). 27시점 모두 받음, 실패 0.
