# Fake Planet Lab (가짜 행성 해부실)

| 항목 | 내용 |
| --- | --- |
| ID | `fake-planet-lab` |
| 상태 | **1차 구현됨** (분석 패널 "Additional analyses"에서 열림) |
| 담당 | 김재현 (`rreenactt`) |
| 출력 종류 | overlay, text |
| 최소 SPHEREx 방문 횟수 | 1 |
| 적용 대상 | 모든 좌표 |
| 화면 배치 | 추가 분석 목록 → "Run" → 다 받으면 패널 왼쪽 탭으로 열림 (결정 #42) |
| 데이터 | IRSA SPHEREx DR1, AWS L2b 바이트 범위, Gaia DR3 |

## 1. 무엇을 알려주나

"움직이는 점처럼 보이지만 실제로는 결함인 것"을 가려낸다. 사용자가 고른 점에 대해 품질 플래그(우주선 흔적, 포화, 유령상, 잔상 등), 신호 대 잡음비, 모양(PSF 대비 크기), 다른 노출에서의 반복, 근처 밝은 별을 점검하고 항목별 결과를 체크리스트로 보여준다.

## 2. 왜 필요한가

- 대부분의 "새 천체 발견" 주장은 검출기 결함에서 나온다. 이 점검이 없으면 블링크에서 깜빡이는 점을 그대로 후보로 믿게 된다.
- 사용자 평가의 세 선택지 중 "Noise or artifact"를 판단하는 근거를 준다. 다른 분석(Neighborhood in Motion의 SPHEREx 비교, Sky Sonata)도 이 코드를 그대로 쓴다.

## 3. 입력 데이터

- IRSA SIA2(`spherex_dr1`)로 좌표를 덮는 노출 목록
- DataLink로 확인한 L2b 파일에서 필요한 행만: IMAGE, FLAGS(RICE_1 압축), VARIANCE, ZODI, WCS-WAVE (AWS 공개 버킷 우선)
- Gaia DR3 밝은 별 (G < 10, 반경 2′, 관측 시점으로 고유운동 이동)
- 원본은 저장하지 않는다.

## 4. 방법

1. **노출 고르기:** 기본으로 서로 다른 방문의 노출 최대 3장을 고른다. 사용자가 바꿀 수 있다.
2. **플래그 해석:** 비트 번호를 코드에 박지 않고 파일 헤더의 `MSKNnnnn`(이름)·`MSKDnnnn`(설명)에서 읽는다. 분류:
   - 측정 제외: NONFUNC, MISSING_DATA, HOT, COLD, SUR_ERROR
   - 오염 경고: 포화, 우주선, 유령상, 잔상, 누화, 줄무늬
   - 맥락: OUTLIER (결함으로 치지 않음, [결정 #28](../decisions.md))
   - 정보: SOURCE, FULLSAMPLE, DICHROIC, PHANMISS
   - 해석 미지원: 그 밖 (모르는 비트는 모른다고 표시)
3. **화면:** 같은 하늘 격자(4′, 북쪽 위)에 최근접 방식으로만 옮겨, 화면 픽셀마다 원본 픽셀 번호를 따라갈 수 있고 플래그 비트가 섞이지 않게 한다. 화면은 IMAGE − ZODI, 모든 방문에 같은 스트레치. 레이어는 색으로만 덮고 영상을 지우지 않는다.
4. **점검 (모두 원본 픽셀에서 계산):**
   - 자료 유효성, 후보 위·주변 6px의 품질 플래그
   - 잘라낸 가장자리와 검출기 가장자리 구분
   - 2px 조리개 S/N (VARIANCE + 배경 오차)
     - 중심 1px 안에서 합산에서 빠진 픽셀 수(`coreExcludedPixels`)를 함께 기록하고 경고 문구로 보인다. 조리개 손실은 면적으로만 판단하는데 점광원의 빛은 중심에 몰려 있어, 중심 픽셀이 포화로 빠지면 면적 8% 손실이어도 밝기는 하한값이 된다(RW Aurigae D1에서 확인). 정보 표시일 뿐이며 `quality`와 판정(`fpl-checks-1`)은 그대로다.
   - PSF 대비 크기·늘어짐 (S/N ≥ 10일 때, 2σ 픽셀, 픽셀화 보정)
   - 다른 독립 노출에서도 보이는지
   - 비교 조건 (같은 검출기, 대역폭 안 파장, 시간)
   - Gaia 밝은 별 근처인지 (유령상·포화 번짐 원인)
5. **판정:** `Quality issue found` / `Needs further review` / `No issue found in current checks`. 항목별 `Issue`·`Caution`·`OK`·`Info`·`Not checked`. 점검하지 않은 항목은 통과로 표시하지 않는다.
6. **기록:** 후보 좌표, 관측 ID, 항목별 결과, 사용자 판정(`Moving` / `Not moving` / `Noise or artifact`), 메모, 원본 URL·읽은 범위·규칙 버전(`fpl-checks-1`)을 브라우저 탭에 쌓고 JSON으로 내려받는다. 서버에는 저장하지 않는다.

7. **밝기 비교 (Brightness 탭, 규칙 `fpl-brightness-1`, `app/_lib/fpl/brightness.ts`):** 고른 검출기의 모든 노출에서 그 자리의 밝기를 원본 픽셀로 잰다. 노출마다 그 자리의 파장이 다르므로 한 방문은 스펙트럼이 되고, 두 방문은 같은 파장을 본 노출끼리 비교한다.
   - **중심(core):** 반경 2px 안의 쓸 수 있는 픽셀 합. 포화되지 않는 광원용.
   - **고리(ring):** 포화된 중심 바깥의 빛. 3–6, 6–10, 10–15px 고리 중 노출의 80% 이상에서 잴 수 있는 가장 안쪽 고리를 자동으로 고른다(사용자가 바꿀 수 있음). 1px 폭 고리마다 쓸 수 있는 픽셀의 평균에 전체 픽셀 수를 곱해, 빠진 픽셀 때문에 합이 바깥쪽으로 치우치지 않게 한다. 쓸 수 있는 픽셀이 절반 미만인 고리는 재지 않는다.
   - 배경은 20–28px 고리의 3σ 클리핑 중앙값.
   - 중심 1px 안 픽셀이 한 노출이라도 빠지면 중심값은 하한이므로 고리로 넘어간다. 고리 밝기는 PSF 날개의 일부라 **상대 밝기**다(같은 검출기·같은 파장끼리만 비교, 전체 밝기 아님).
   - **방문 간 짝:** 같은 검출기에서 파장 차이가 대역폭의 0.5배 미만인 노출끼리, 가까운 것부터 한 번씩만 짝짓는다. 짝마다 나중 ÷ 먼저 비율을 구한다.
   - **요약:** 비율의 중앙값을 등급으로 바꾸고, 오차는 짝들의 흩어짐(1.4826 × MAD / √N, 측정 오차보다 작으면 측정 오차)으로 잡는다. `Brightness changed`는 짝 3개 이상, 0.05등급 이상, 3σ 이상일 때만. 그 밖은 `No change found` 또는 `Too few pairs to say`. 원인을 말하지 않는다(조리개 안 이웃 별, 검출기 효과도 수치를 바꿀 수 있음).
   - 노출 한 장을 읽는 데 몇 초가 걸려 검출기를 골라서 재고(한 번에 6장), 결과는 검출기를 더할 때 쌓인다.

## 5. 출력

- **overlay:** 원인별 플래그 레이어 (켜고 끄기)
- **text:** 항목별 체크리스트와 종합 판정, 픽셀을 누르면 그 픽셀의 모든 비트 설명
- **기록:** JSON 내려받기
- **Brightness 탭:** 방문 쌍·검출기별 변화 표(짝 수, 비율, 등급 변화 ± 오차, 결과), 파장 대비 밝기 그림(방문별 색, 하한은 세모), 측정값 JSON 복사

## 6. 한계와 주의

- 플래그가 모든 결함을 잡지는 못한다. "No issue found"는 "진짜 천체"라는 뜻이 아니라고 화면에 적는다.
- OUTLIER는 움직이는 천체에도 붙으므로 결함 근거로 쓰지 않는다.
- 밝기 비교: 고리 밝기는 PSF 크기(파장에 따라 변함)를 따라가므로 파장에 따른 기울기는 광원의 스펙트럼이 아니다. 포화 번짐(bloom)이 고리에 남으면 값이 달라질 수 있어, 다른 고리에서도 같은 변화가 나오는지 확인해야 한다. 밝은 별의 중심 2px 값은 중심 픽셀이 빠지지 않은 노출끼리도 크게 흩어졌다(RW Aurigae D1, 42–180 mJy). 조리개 보정과 PSF 맞춤은 없다.
- PSF 모델 기반 형태 점검, 합성·실제 사례 갤러리, 자동 후보 제안은 없다.

## 7. 검증

- Barnard's Star(2025 위치) 중심: BLOOM·OVERFLOW·TRANSIENT·SUR_ERROR가 잡혀 `Quality issue found`. 밝은 별 점검이 이 별 자체(G 8.2, 1.9″)를 찾음.
- 네 비트가 겹친 픽셀(TRANSIENT+SUR_ERROR+NONFUNC+SOURCE)을 정확히 풀어 보임.
- 주변 밝은 별 4개의 크기 7.4–11.0″ (PSF 7.4″) → 점광원으로 판정.
- FLAGS 압축 해제를 IRSA 잘라내기와 대조해 5,112픽셀 일치했다고 적었으나 비교 기록이 남아 있지 않다. 기록을 다시 확보하기 전까지 검증 성과로 쓰지 않는다.

- 밝기 비교 (2026-11-15, 보관소 502로 일부 노출은 못 읽음):
  - **R Draconis** D1(0.75–1.1µm) 27장: 중심이 6px 넘게 포화되어 3–6px 고리는 못 잼 → 6–10px 고리 자동 선택. 방문 2(2025-07) → 방문 3(2025-10): 나중 ÷ 먼저 0.57, **+0.62 ± 0.10등급 어두워짐**(짝 4개, `Brightness changed`). 10–15px 고리도 0.55, +0.64 ± 0.09등급(짝 5개)으로 일치. 화면에서 다시 돌렸을 때(읽힌 노출이 더 많음)는 짝 7개, 0.47, +0.83 ± 0.14등급으로 같은 방향. 방문 1과의 비교는 짝이 1–2개라 `Too few pairs to say`.
  - **RW Aurigae** D1·D4 57장: 중심 픽셀이 빠진 노출이 있어 고리로 측정. 방문 1(2025-09) → 방문 2(2026-03): 6–10px 고리 +2%(−0.024 ± 0.027등급, 짝 23개), 10–15px 고리 −0.5% → `No change found`. 3–6px 고리는 검출기별로 값이 갈려(D1 +26%, D4 −9%) 변화로 보지 않는다.
