# 기본 분석: 블링크 (Blink · Difference · Stack)

## 1. 무엇을 알려주나

사용자가 고른 하늘 한 지점을 SPHEREx가 찍은 방문(약 6개월 간격)마다 한 장씩 보여주고, 그 장들을 번갈아 재생(블링크)하거나 첫 방문과의 차이(차분), 전체 평균(합산)으로 보여준다. 방문 사이에 자리를 옮긴 점이 있으면 블링크에서 깜빡이고, 차분에서 파랑·주황 쌍으로 남는다. 각 방문 날짜로 옮긴 Gaia 별 위치를 겹쳐서 "이미 알려진 별"과 구분한다.

## 2. 왜 필요한가

- 움직이는 천체 후보를 사람이 확인하는 출발점이다. 프로젝트 콘셉트("기계가 후보를 찾고, 사람이 확인한다")에서 사람이 보는 화면이 이것이다.
- SPHEREx는 LVF(선형 가변 필터)라 같은 검출기라도 이미지 안 위치마다 파장이 다르다. 아무 노출이나 섞으면 파장 차이로 밝기가 달라져 "변화"처럼 보인다. 기본 분석은 **같은 검출기·비슷한 파장**의 노출만 골라 이 오해를 막는다 (절대 원칙 3).
- 목표를 중앙에 맞추면 움직임이 사라지므로 **입력 좌표 기준 고정 하늘 격자**에 놓는다 (절대 원칙 2).

## 3. 입력 데이터

| 자료 | 받는 곳 | 쓰는 것 |
| --- | --- | --- |
| 노출 목록 | IRSA SIA2 `COLLECTION=spherex_dr1`, 좌표 반경 0.0005° | `obs_id`, 검출기, 관측 시각(`t_min`·`t_max`), 네 꼭짓점(`s_region`) |
| 파일 위치 | IRSA DataLink (`ivo://irsa.ipac/spherex_dr1?<obs_id>/<D#>`) | `#this` 파일과 `cloud_access`(AWS 버킷 키) |
| 픽셀 | AWS `nasa-irsa-spherex` (us-east-1) L2b, HTTP 바이트 범위 | IMAGE, FLAGS(RICE_1 압축), VARIANCE, ZODI, WCS-WAVE. 시야 주변 48×48 픽셀만 |
| 별 위치 | Gaia DR3 (ESA Gaia Archive 우선, 실패 시 IRSA) | G < 16, 반경 130″, 방문 날짜로 고유운동 이동 |

원본 FITS는 저장하지 않는다 (절대 원칙 7).

## 4. 방법

### 서버: 계획 만들기 (`/api/blink/plan`)

1. **관측 검색:** SIA2로 그 지점을 덮는 DR1 과학 노출을 모두 받는다. 같은 노출·검출기는 하나만 남긴다. 개수 상한으로 자르지 않는다.
2. **방문 묶기:** 시간순으로 정렬해 20일 넘게 떨어지면 새 방문으로 나눈다.
3. **검출기 고르기:** 노출이 가장 많은 검출기(같으면 방문 수가 많은 쪽). 사용자가 D1–D6 칩으로 바꿀 수 있다.
4. **목표 위치의 파장 추정 (파일을 다 읽지 않고):** 노출마다 SIA2의 네 꼭짓점이 검출기 픽셀 (0,0)·(W,0)·(W,H)·(0,H)에 대응한다는 점을 이용해, 목표 좌표를 TAN 투영한 뒤 쌍선형 역변환(뉴턴 반복)으로 검출기 픽셀을 구한다. 그 픽셀의 파장·대역폭을 검출기의 `WCS-WAVE` 표(첫 파일에서 한 번 읽음)로 계산한다. 추정 오차는 약 0.001 µm로 허용치(0.01–0.03 µm)보다 훨씬 작다.
5. **기준 파장과 허용치 ([결정 #30](../decisions.md), 제안):** 허용치는 목표 위치 대역폭의 ±0.5배. 후보 파장 중 허용치 안의 노출이 있는 방문 수가 가장 많은 값(같으면 노출 수가 많은 값)을 기준으로 고른다.
6. **방문별 선택:** 허용치 안의 노출을 파장이 가까운 순으로 최대 3장 고른다. 빠진 노출에는 이유를 남긴다(검출기 밖, 파장 밖, 3장 초과).
7. **상태:** 쓸 수 있는 방문 2개 이상 `comparable`, 1개 `additional-analysis-needed`, 0개 `no-observations`.

### 브라우저: 이미지 만들기 (`app/_components/blink/blink-context.tsx`)

1. 계획에 든 노출의 48×48 픽셀 잘라내기를 모두 동시에 받는다 (`/api/fpl/frame`).
2. **파장 재확인:** 받은 파일의 `WCS-WAVE`로 목표 픽셀 파장을 다시 계산해, 기준 ± 허용치를 벗어나면 그 노출을 뺀다.
3. **배경과 불량 픽셀:** IMAGE − ZODI(황도광 모델)로 계절 배경 차이를 없앤다. NONFUNC·MISSING_DATA·HOT·COLD·SUR_ERROR·TRANSIENT·SNOWBALL 비트만 가린다. **OUTLIER는 가리지 않는다** (움직이는 천체가 여기에 걸림, [결정 #28](../decisions.md)).
4. **고정 격자:** 입력 좌표 중심 3′×3′, 96×96(1.875″/픽셀), 북쪽 위·동쪽 왼쪽 격자에 쌍선형 재투영한다.
5. **방문별 합치기:** 같은 방문의 노출을 픽셀별 중앙값으로 합친다.
6. **보기:**
   - Blink: 방문을 시간순으로 번갈아 보인다. 모든 방문에 **같은 화면 범위**(전체 1–99.5 백분위)를 써서 화면 밝기 차이가 대비 조정 때문에 생기지 않게 한다.
   - Difference: 지금 방문 − 첫 방문. 0을 회색, 음수 파랑, 양수 주황.
   - Stack: 모든 방문 평균. 어두운 고정 천체를 보기 좋다.
7. **Gaia 겹치기:** 방문마다 쓴 노출의 평균 시각으로 Gaia 별을 옮겨 원으로 그린다.

### 로딩 ([결정 #31](../decisions.md), 제안)

패널은 계획 + 모든 이미지 + 방문별 Gaia를 다 받은 뒤 열린다. 그동안 진행바에 단계와 "받은 수 / 전체"를 보인다.

## 5. 출력

- **요약:** 방문 수, 기간, 검출기, 기준 파장 ± 허용치, 상태. 허용치 안 프레임이 없는 방문이 있으면 "3 visits (1 of 4 without a D1 frame in tolerance)"처럼 함께 적는다
- **방문 번호:** 슬라이더는 "보이는 방문 중 위치 / 보이는 방문 수 · Visit 원래 번호"(예: `3 / 3 · Visit 4`)로 표시한다. 원래 번호는 아래 노출 목록과 같아서, 프레임이 없는 방문은 건너뛴다
- **뷰어:** Blink / Difference / Stack, 재생·속도·확대, 검출기 칩(파장 범위·방문 수)
- **노출 표:** 방문마다 쓴 노출과 뺀 노출(이유), 측정 파장, 목표 위치 플래그, IRSA 원본 링크
- **결과 없음:** 관측 0건이면 "관측 없음", 방문 1회면 "SPHEREx만으로는 비교 불가 · 추가 분석으로 비교"

## 6. 한계와 주의

- 블링크·차분은 SPHEREx끼리, 같은 검출기·비슷한 파장끼리만 한다. 다른 탐사와의 밝기 비교·차분은 하지 않는다.
- 차분에 남은 무늬는 이동뿐 아니라 PSF·정렬 오차·파장 차이(허용치 안)로도 생긴다. 판정이 아니라 "볼 곳"이다.
- 허용치 ±0.5×대역폭은 제안값이다 (팀 확정 필요).
- 알려진 소행성 겹치기, 사용자 평가 저장은 아직 없다.

## 7. 검증

- Barnard's Star: 방문 3개(노출 4장), 블링크에서 별이 북쪽으로 움직이는 것과 Gaia 예측 위치가 겹치는 것을 확인. 패널 표시까지 약 7–14초(한국 PC).
- 꼭짓점 기반 파장 추정과 파일에서 읽은 실제 파장 차이 약 0.001 µm.
